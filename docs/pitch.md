# 5 分钟讲解稿 + 简历要点

## 一、5 分钟现场讲解（照着念也行）

### 0:00–0:40 一句话定位

> 这是一个给中小工厂 / 电商商家用的**自然语言数据分析助手**。
> 老板不会写 SQL，但每天都要问"上个月哪个渠道亏了""哪个产品卖得最好"。
> 这个系统把一句中文问题变成：**可执行的只读 SQL + 一张图 + 一句人话结论**，
> 并且能说清结论是从哪几行数据算出来的。

### 0:40–1:40 演示（现场操作）

1. 打开 `http://localhost:8080`，用 `admin / admin12345` 登录。
   —— *"系统预置了一份门店数据：4 个城市、3 个渠道、5 个产品、1200 行订单。"*
2. 问："**各城市的销售额排名**"
   —— 界面上会先出现"当前节点：生成 SQL"，然后 SQL 出现、柱状图出现、结论出现。
   —— *"注意这里流式输出的不是模拟打字，是 LangGraph 每个节点执行完就推一个事件。"*
3. 问："**哪个渠道的利润最低，为什么**"
   —— 这次走了诊断分支：原因 + 证据（引用具体数值）+ 建议。
4. 问："**帮我看看销售情况**"
   —— Agent 不猜，反问你"想看哪个指标"，并给出 3 个可点选项。
   —— *"这是我最想强调的一个点：模糊的时候敢于说'我不知道'，比编一个答案重要。"*

### 1:40–2:40 三个技术取舍（这是面试官真正想听的）

**① SQL 安全闸为什么放在执行侧**

> 提示词一定会被注入绕过。所以我在 `execute_query` 执行前放了一道白名单式的闸：
> 只允许 SELECT/WITH/EXPLAIN，单语句、长度上限、自动补 LIMIT、拦危险函数。
> 关键实现细节是**先给字符串字面量和注释打码再判关键字**——所以
> `WHERE note='delete me'` 不会误伤，而 `SELECT 1; DROP TABLE x` 一定被拦。
> 现场可以点开 `/api/sql/validate` 给你们看判定结果，7 类攻击样本全部拒绝。

**② 定时任务怎么保证不重复执行**

> 没有用分布式锁，而是把幂等做进数据库：
> `schedule_runs(schedule_id, scheduled_for)` 加唯一约束，抢到才执行。
> 抢不到说明别的进程已经抢了，顺手把 `next_run_at` 往前推一格——否则它会每轮都撞同一个键。
> 重启重放、多副本并发都被数据库挡住。失败隔离是单条计划失败只影响自己，
> 连续失败 3 次自动停用，避免持续告警。

**③ 为什么有一个 mock LLM**

> CI 不能依赖付费 Key，但"图路由、JSON 解析、SQL 闸、重试、图表生成"这些机制必须有回归门。
> 所以我做了确定性 MockLLM，配 `bench/agent_baseline.py` 逐项比对基线，
> 任何一项从 true 变成 false 就退非 0。它**不衡量模型能力**——
> 准确率看我归档的 309 条真实 DeepSeek 评测：5 套数据，其中 2 套是完全没参与调参的留出集。

### 2:40–3:30 工程化（说明这不是个 demo 玩具）

> 我接手的时候这个项目 95 个测试是绿的，但**认证模块只剩 .pyc**、没有迁移、
> 前端 `npm run build` 直接失败。审计写在 `docs/audit.md` 里。
>
> 现在：268 个测试、覆盖率 73%（门槛 70%）、ruff 干净、五个 CI job
> （后端 / 空库迁移 + `alembic check` / 前端 / pip-audit + Trivy / 三个镜像可构建）。
>
> 迁移那块值得说一句：`models/__init__.py` 原来是空的，`operation_logs` 这张表
> **从来没被创建过**——因为没人 import 它的 model。这类问题只有真的跑一遍才看得见。

### 3:30–4:30 我知道的边界（主动说，别等人问）

> - 元数据库是 SQLite，api 和 worker 两个进程共享一个文件，靠 WAL + `busy_timeout` 扛。
>   多租户必须换 PostgreSQL，这是定位问题不是技术债。
> - 限流是进程内的，多副本会放大 N 倍，精确限流需要 Redis。
> - 任务队列也是进程内的，靠"先落库再入队 + 重启恢复"兜底，没有跨进程抢占锁。
> - 调度器没有领导者选举，只是用唯一约束保证幂等。
>
> 这些写在 `docs/architecture.md §5`，是**与"单机面向中小商家"定位一致的取舍**，
> 不是没想到。

### 4:30–5:00 如果继续做

1. **SQL 审核从"规则"升级到"规则 + 结果对账"**：现在已有数值域校验和总额对账，
   下一步让它在结果异常时自动二次查询验证，而不是只提示用户核对。
2. **数据源质量前置**：画像已经能标出缺失率和 PII，下一步在提问时直接把
   "这列 62% 是空"告诉模型，让它主动换维度。
3. **多租户**：PostgreSQL + 行级隔离 + Redis 限流，那时才值得上这些组件。

## 二、3 条简历要点（可直接用）

> **对话式数据分析 Agent｜Python / FastAPI / LangGraph / Vue3**
>
> - 设计并实现 8 节点 LangGraph 分析链路（意图理解 → 澄清 → NL2SQL → 只读执行 → 分析 → 诊断 → 可视化 → 回答），
>   支持节点级 SSE 流式、SQL 失败回写重试、多数据源并行与部分成功降级；在 5 套数据集 **309 条 NL2SQL 用例**上
>   正确率与可执行率均达 **100%**（含 2 套未参与调参的留出集），平均生成延迟 1.5–2.1s。
>
> - 在**执行侧**落地 SQL 只读安全策略（单语句 / 长度上限 / 危险函数 / 自动 LIMIT / 单元格上限），
>   用"字面量与注释打码后再判关键字"避免误伤；7 类注入与破坏性输入全部拦截，并把判定做成可调试的
>   `POST /api/sql/validate`。
>
> - 补齐工程化最后一公里：JWT + refresh 轮换 + admin/analyst/viewer 三级 RBAC、Alembic 迁移与启动自愈、
>   数据源 CRUD 与上传清洗（幂等增量、路径穿越防护）、报告落库、定时分析（数据库唯一约束幂等 + 失败隔离）、
>   统一错误体与 request_id、`/healthz /readyz /metrics`；后端测试从 95 增至 **268**，覆盖率 73%，
>   建 5 个 CI job（含空库迁移校验、pip-audit / Trivy），CI 全程不依赖付费 Key。

> 备选（更偏数据/AI 方向时替换第一条）：
> 设计**上下文压缩**方案解决长会话膨胀：LLM 摘要 + 抽取式兜底的混合策略，在 24 段会话 × 15 个埋点事实的
> 评测中把事实留存从纯抽取式的 **4.2%** 提升到 **100%**，token 压到 31.2%。

## 三、可能被追问的 6 个问题（附答法）

| 问题 | 怎么答 |
|---|---|
| 为什么不用 Text2SQL 微调？ | 数据量不够且业务口径变化快；用 schema linking + sample_values + 列归属校验把"猜列名"空间压小，实测已经 100%，微调收益不抵维护成本 |
| 怎么防幻觉？ | 三层：schema 里给真实取值（治"黄金会员 vs 黄金"）、执行前校验列归属、0 行结果不许编结论；结果还有数值域与总额对账 |
| 为什么不留写操作？ | 产品定位是"分析"，写操作只会带来不可逆风险；且 `SQL_ALLOW_WRITE_FOR_ADMIN` 默认 false，纵深防御 |
| 覆盖率 73% 为什么不是 90%？ | 缺口主要在 LLM 调用分支和 PDF 字体分支，这些是"必须外部依赖"的路径；我把资源投在**机制型断言**（基线回归门）而不是刷行数 |
| 单机 SQLite 撑得住吗？ | 一天几十个长任务、并发几个用户完全够；真正瓶颈是单写者，所以 WAL + busy_timeout，并在文档里写清换成 PostgreSQL 的触发条件 |
| 这套东西你自己写还是 AI 写的？ | 骨架已有；我做的部分是审计 → 认证/RBAC/迁移/管道/调度/可观测/CI 的补齐与纠错（例如 `operation_logs` 从未建表、上传路径穿越、pandas 把 `0012` 转成 `12.0`），每一步都有测试和命令输出兜底 |
